# 连到另一台电脑

- 日期：2026-11-20
- 相关：[桌面应用](2026-10-16-desktop-app.md)

## 为什么

桌面应用默认自己启动一份 DSH，数据在自己这台电脑上。但用户常常把 Bot 团队跑在一台常开的电脑（比如 Mac mini）上，再从另一台电脑用浏览器打开它的网址。用浏览器看不到桌面应用给的东西（托盘、窗口、下载、Bot 的浏览器标签），而且每次都要自己记住地址。

所以给桌面应用加一种启动方式：不启动自己的引擎，直接打开另一台电脑上已经在跑的 DS Bot。

## 怎么用

```sh
open -a "DS Bot" --args --remote http://192.168.1.20:7331
# 或者
DS_BOT_REMOTE=http://192.168.1.20:7331 npm start
```

地址只收 http 或 https，去掉查询参数、`#` 和结尾的斜杠（`src/remote-url.mjs`，有测试）。没有这个参数时，应用和以前完全一样。

## 已定的行为

- **不启动引擎，不碰数据目录。** 跳过位置选择、导入询问、`restoreSessions` 和 `startEngine`；启动窗口的数据和引擎两段直接算完成。
- **窗口的 origin 用对方的。** `origin` 取远程地址的 origin，窗口的跳转守卫因此把对方的页面留在窗口里，别处的链接照旧用系统浏览器打开。
- **失败就是失败。** 对方没开、地址写错、页面加载不出来时，窗口停在空白页；应用不会退回去启动本机引擎，免得两套数据悄悄并存。

## 还没做

- 没有输入地址的界面：现在只能靠参数或环境变量，第一次用要自己写地址。下一步在启动窗口里加一页「连到另一台电脑」，把地址记在 `locations.json` 旁边。
- 远程模式下的托盘和菜单还留着本机的项（重启引擎、更新、日志），点了没有意义，应当隐藏。
- 没在真窗口里跑过：这次只跑了逻辑测试（地址解析）和整个应用的单元测试。等有显示器时再验一次。
